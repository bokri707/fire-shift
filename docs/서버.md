## 표
| 표 | 용도 |
|---|---|
| teams | 소모임(코드, 이름, 기준일, 종류 `kind`: team=근무 팀 / meet=모임, `pair`: 부부(가족) 소모임 표시) |
| members | 소모임 팀원(이름, 팀 번호, 기준일, 연가·교육·패턴 `ex`) |
| polls | 투표·모임·팀 일정(제목, 후보 날짜, 확정일 `final`) |
| votes | 투표 결과(투표, 팀원, 가능한 날짜) |
| usage_daily | 날짜·종류별 사용 횟수 합계 |
| miss_log | 없는 소모임 코드를 조회한 기록(접속 주소·코드의 md5, 시각). 1시간 뒤 지움 |

팀을 지우면 팀원·투표가 같이 지워집니다(ON DELETE CASCADE).

## 서버 함수 (모두 SECURITY DEFINER)
| 함수 | 하는 일 |
|---|---|
| create_team / create_team_k | 소모임 만들기 (코드는 한글·영문·숫자 2~12자). `create_team_k`는 종류(team/meet)도 받음. 예전 `create_team`은 옛 앱 호환용으로 남김 |
| set_team_kind | 소모임 종류 바꾸기 (같은 소모임의 모두에게 적용) |
| set_team_pair | 부부(가족) 소모임 표시 켜기·끄기 (같은 소모임의 모두에게 적용) |
| get_team | 코드로 소모임 정보 확인 (이름·기준일·종류) |
| upsert_member / delete_member | 팀원 정보 올리기·지우기 |
| insert_poll / update_poll / delete_poll | 투표·일정 올리기·수정·지우기 |
| upsert_vote | 투표하기 |
| fetch_team / fetch_team_v2 | 팀원·투표 받기 (v2는 바뀐 게 없으면 데이터 생략) |
| bump_usage | 사용 횟수 +1 (open/cal/team/pair/set만 허용) |
| _guard_code, _client_ip | 코드 추측 제한용 도우미. 앱에서 직접 부를 수 없고 get_team·fetch_team 안에서만 씀 |

각 함수는 길이·개수 제한을 확인합니다(이름 20자, 제목 30자, 날짜 120개, `ex` 30000자 등).

## 접근 방식과 보안
- 모든 표는 RLS가 켜져 있고 정책이 없어 **직접 읽고 쓸 수 없습니다**.
- 앱은 위 함수로만 접근합니다. 함수는 익명 키(anon)로 실행할 수 있게 열려 있습니다.
- 따라서 **팀 코드를 아는 사람은 그 소모임을 읽고 고칠 수 있습니다.** 팀 코드가 사실상 유일한 비밀번호입니다.
- 키: publishable 키만 앱에 들어 있습니다. secret/service_role 키는 어디에도 넣지 않습니다.

## 코드 추측 제한 (2026-11-01 적용)
- `get_team`, `fetch_team`(`fetch_team_v2`도 이것을 부름)은 먼저 `_guard_code`를 거칩니다.
- 한 접속 주소가 10분 안에 없는 코드를 **30가지** 틀리면, 그 주소의 조회를 모두 막습니다(오류 `too_many_tries`, 앱에는 "서버에 연결하지 못했습니다"). 가장 오래된 기록이 10분을 넘기면 자동으로 풀립니다.
- 같은 코드를 반복 조회하면 1번으로 칩니다. 지워진 소모임을 계속 동기화하는 폰이 막히지 않게 하기 위해서입니다.
- 접속 주소는 위조할 수 없는 `cf-connecting-ip`만 씁니다. `x-forwarded-for`와 `true-client-ip`는 위조되는 것을 시험으로 확인했습니다.
- 표에는 md5만 남습니다. 그래도 접속 주소에서 나온 값이므로 개인정보처리방침에 적어야 합니다.
- 되돌리기: `supabase/rollback_rate_limit.sql`을 SQL 편집기에서 실행합니다.

## 알려진 약점 (2026-11-01 갱신)
1. 지금 쓰는 소모임 코드 19개 중 17개는 예전 추천 방식이라 짧습니다. 새 코드는 무작위 12자지만 기존 코드는 그대로이고, 위 제한이 보호합니다. 접속 주소를 바꿔 가며 시도하면 완전히 막지는 못합니다.
2. 쓰기 함수(`upsert_member`, `insert_poll`)는 코드가 없을 때 `no team` 오류를 내므로 코드가 있는지 알아낼 수 있습니다. 이 함수들에는 추측 제한이 없습니다.
3. 팀원별 인증(토큰)이 없어 다른 팀원의 기록을 같은 소모임 안에서 고칠 수 있습니다. → 팀원별 비밀 토큰 도입.
4. Supabase 보안 점검에서 "SECURITY DEFINER 함수를 익명이 실행 가능" 경고가 14건(로그인 사용자 기준으로 14건 더) 나옵니다. 위 구조상 의도된 것입니다.
5. `usage_daily`에 한 번에 수천 번 호출하는 것을 막지 않습니다(통계가 부풀려질 수 있음).
