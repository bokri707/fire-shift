## 표
| 표 | 용도 |
|---|---|
| teams | 소모임(코드, 이름, 기준일) |
| members | 소모임 팀원(이름, 팀 번호, 기준일, 연가·교육·패턴 `ex`) |
| polls | 투표·모임·팀 일정(제목, 후보 날짜, 확정일 `final`) |
| votes | 투표 결과(투표, 팀원, 가능한 날짜) |
| usage_daily | 날짜·종류별 사용 횟수 합계 |

팀을 지우면 팀원·투표가 같이 지워집니다(ON DELETE CASCADE).

## 서버 함수 (모두 SECURITY DEFINER)
| 함수 | 하는 일 |
|---|---|
| create_team | 소모임 만들기 (코드는 한글·영문·숫자 2~12자) |
| get_team | 코드로 소모임 정보 확인 |
| upsert_member / delete_member | 팀원 정보 올리기·지우기 |
| insert_poll / update_poll / delete_poll | 투표·일정 올리기·수정·지우기 |
| upsert_vote | 투표하기 |
| fetch_team / fetch_team_v2 | 팀원·투표 받기 (v2는 바뀐 게 없으면 데이터 생략) |
| bump_usage | 사용 횟수 +1 (open/cal/team/pair/set만 허용) |

각 함수는 길이·개수 제한을 확인합니다(이름 20자, 제목 30자, 날짜 120개, `ex` 30000자 등).

## 접근 방식과 보안
- 모든 표는 RLS가 켜져 있고 정책이 없어 **직접 읽고 쓸 수 없습니다**.
- 앱은 위 함수로만 접근합니다. 함수는 익명 키(anon)로 실행할 수 있게 열려 있습니다.
- 따라서 **팀 코드를 아는 사람은 그 소모임을 읽고 고칠 수 있습니다.** 팀 코드가 사실상 유일한 비밀번호입니다.
- 키: publishable 키만 앱에 들어 있습니다. secret/service_role 키는 어디에도 넣지 않습니다.

## 알려진 약점 (2026-10-31 점검)
1. 팀 코드가 추측하기 쉬우면 남이 들어올 수 있습니다. → 코드를 길고 무작위로 만들도록 바꾸기.
2. 호출 횟수 제한이 없습니다. → 요청 제한 또는 함수 안 제한 추가.
3. 팀원별 인증(토큰)이 없어 다른 팀원의 기록을 같은 소모임 안에서 고칠 수 있습니다. → 팀원별 비밀 토큰 도입.
4. Supabase 보안 점검에서 "SECURITY DEFINER 함수를 익명이 실행 가능" 경고 10건이 나옵니다. 위 구조상 의도된 것입니다.
5. `usage_daily`에 한 번에 수천 번 호출하는 것을 막지 않습니다(통계가 부풀려질 수 있음).
