# 구글 플레이 출시 체크리스트 (소방 교대달력으로 한 번 해 본 기록)

작성: 2026-11-05. 구글 화면 기준이라 화면이 바뀌면 이 문서도 고치세요.
다음 앱을 올릴 때 **순서대로 따라 하면 됩니다.** 각 칸 오른쪽의 "이 앱에서 고른 답"은 참고용이며, **앱마다 코드를 보고 답을 새로 정합니다.** 그대로 복사하지 마세요.

- [x] AdMob 계정

## 1. 시작 전에 정할 것 (앱마다)

- [ ] 앱 이름(30자 이내), 패키지 이름(한 번 올리면 못 바꿈, 예: kr.fireshift.app)
- [ ] 무료로 낼지(무료 앱 + 앱 안 구독은 가능, 유료 앱은 무료로 못 바꿈)
- [ ] 로그인이 있는지, 사용자 글을 받는지, 어떤 개인정보를 모으는지(신고 답이 여기서 정해짐)
- [ ] 개인정보처리방침·이용약관 공개 주소(웹에 올려 둠: privacy.html, terms.html)
- [ ] 문의 이메일, 앱 아이콘, 소개 문구

## 2. 앱 만들기

- [ ] 구글 플레이 콘솔 → 앱 만들기
- 이름 / 패키지 이름 / 기본 언어 **한국어** / 앱 / **무료** / 정책·수출법 동의 체크
- 이 앱에서 고른 답: 위와 같음.

## 3. 앱 콘텐츠 신고 11개 (가장 오래 걸림, 대시보드 "앱 설정 완료"에서)

| 항목 | 이 앱에서 고른 답 | 다음 앱에서 확인할 것 |
|---|---|---|
| 앱 액세스(로그인) | 아니요(로그인 없음) | 로그인이 있으면 심사용 테스트 계정 필요 |
| 광고 | 예, 광고 있음 | 광고를 붙였는지 |
| 콘텐츠 등급 | 카테고리 "다른 모든 앱 유형". 사용자 콘텐츠 공유 예, 나머지 설문은 대부분 아니요, 초대된 친구로만 제한 예. 결과 전체이용가(3세) | 사용자 글, 위치, 결제, 도박 등이 있으면 답이 달라짐. 구독·결제를 붙이면 "디지털 상품 구매"를 예로 |
| 정부 앱 | 아니요 | 기관 앱이면 증빙 필요 |
| 금융 기능 | 해당 없음 | 결제·송금·암호화폐가 있으면 체크 |
| 타겟층 및 콘텐츠 | 만 18세 이상만(어린이 대상 아님) | 어린이 대상이면 정책이 훨씬 엄격해져 광고가 어려움 |
| 데이터 보안 | 아래 5장 표 | **앱마다 새로.** 코드가 서버로 보내는 것을 확인 |
| 광고 ID | 예(광고 목적) | 광고 도구가 광고 ID를 쓰면 필수 |
| 건강 앱 | 건강 기능 없음 | 건강·의료 기능이 있으면 별도 |
| 판매자 상태(앱 수준) | 적용됨, 이용약관 주소 입력 | 약관 주소는 앱마다 |
| 개인정보처리방침 | 공개 주소 입력 | 방침 내용은 앱 동작과 같아야 함 |

## 4. 스토어 설정과 등록정보

- [ ] 스토어 설정: 카테고리(이 앱은 **생산성**), 태그, 연락처 이메일(전화번호·웹사이트는 선택)
- [ ] 기본 스토어 등록정보: 앱 이름, **간단한 설명 80자**, **자세한 설명 4000자**
- [ ] 그래픽
  - 앱 아이콘 **512x512** PNG(투명 없음)
  - 대표 이미지 **1024x500** PNG(투명 없음)
  - 폰 스크린샷 **2~8장**, **가로세로 비율 9:16**, 한 변 320~3840px. 세로로 너무 긴 캡처(예: 2:5 비율)는 막힘 → 위쪽 주소창과 아래쪽 버튼 줄을 빼고 9:16으로 자를 것
- [ ] AI 에셋 선언: AI가 만든 이미지가 있으면 라벨(정직하게 표시)
- 문구 원칙: "일반인이 만든 개인 앱, 소방청이나 기관의 공식 서비스가 아님", "광고 있음"을 넣음. "1위", "필수 앱" 같은 과장 금지.
- 스크린샷에 실명, 소모임 코드, 이메일이 보이지 않게(예시 데이터로 찍기).

## 5. 데이터 보안 설문 답 표 (이 앱 기준, 앱마다 코드를 보고 새로 정함)

기본 질문: 데이터 수집 예 / 전송 중 암호화 예 / 삭제 요청 방법 제공 예(방침 주소) / 계정 생성 허용 안 함 / 외부 계정 로그인 아니요.

| 데이터 | 수집·공유 | 필수/선택 | 목적 |
|---|---|---|---|
| 이름(별명) | 수집만 | 선택 | 앱 기능 |
| 위치: 대략적인 위치(광고 도구가 IP로 추정) | 수집+공유 | 필수 | 광고, 분석, 사기 방지 |
| 캘린더 일정(소모임에 올리는 일정) | 수집만 | 선택 | 앱 기능 |
| 앱 정보 및 성능: 비정상 종료 로그, 진단(광고 도구) | 수집+공유 | 필수 | 분석, 사기 방지 |
| 앱 활동: 앱 상호작용 | 수집+공유 | 필수 | 앱 기능, 분석, 광고, 사기 방지 |
| 앱 활동: 기타 사용자 제작 콘텐츠(모임 제목, 문의 글) | 수집만 | 선택 | 앱 기능 |
| 기기 또는 기타 ID(광고 ID) | 수집+공유 | 필수 | 광고, 분석, 사기 방지 |

- "공유"는 구글 광고 도구(AdMob)가 자동으로 모아 구글이 쓰는 것. 서버 업체(Supabase)는 "공유"로 보지 않음.
- 임시 처리 질문은 모두 "아니요".
- 새 기능(사진, 위치, 결제 등)이 들어가면 **올리기 전에** 이 설문과 방침을 먼저 고칠 것.

## 6. 빌드(AAB)

- [ ] `eas.json`의 production 프로필(안드로이드는 기본으로 AAB). 버전 번호는 자동으로 올라감.
- [ ] 최신 코드를 GitHub에 올리고 `npx.cmd tsc --noEmit` 통과 확인(EAS는 올린 코드가 아니라 PC 폴더를 올림. 둘이 같게)
- [ ] Expo 토큰 만들기(expo.dev → Access tokens). **채팅에 붙이지 말고, 화면 캡처에 토큰이 보이지 않게.**
- [ ] 새 PowerShell 창에서 한 줄씩: 폴더로 이동 → `$env:EXPO_TOKEN="토큰"` → `npx.cmd eas-cli build --platform android --profile production`
- 무료 계정은 순서 대기가 길 수 있음(이번 22분 대기, 실제 빌드 8분, 총 31분). 창은 닫지 말 것. "Could not fetch the build status"는 잠깐 인터넷이 끊긴 것이라 빌드와 무관.
- [ ] 끝나면 Expo 빌드 페이지에서 `.aab` 다운로드, 토큰 삭제
- [ ] 서명 키 백업은 다음에 토큰을 만들 때 같이(구글 플레이 앱 서명이라 잃어도 재설정 가능)

## 7. 비공개 테스트(처음 낼 때 필수: 12명 이상, 14일 연속)

- [ ] 테스트 및 출시 → 비공개 테스트 → 이메일 목록 만들기(이메일은 콘솔에만, 채팅·코드에 남기지 않음)
- [ ] 국가: 대한민국만
- [ ] 새 버전 만들기: `.aab` 올리기, 출시명, 출시 노트(`<ko-KR>` 줄은 지우지 말고 사이만 고침)
- [ ] 게시 개요 → 검토를 위해 변경사항 제출(빠른 검사가 돌고 끝나면 전송됨)
- [ ] 구글 검토(처음엔 며칠) → 통과 후 테스터에게 참여 링크 → 12명 참여 시작부터 14일 → 프로덕션 액세스 신청 → 정식 출시
- 14일은 12명이 참여를 시작한 날부터 센다. 그래서 검토를 기다리는 동안 테스터를 모은다.
- 테스터 선물은 별점·리뷰와 무관하게(구글 정책). 모집 글에는 안드로이드만 참여 가능이라고 적는다.
- 웹 안 모집 배너(안드로이드 웹 방문자만)는 설정 한 줄(`TESTER_RECRUIT`)로 끄고 켠다.

## 8. 출시 후

- [ ] AdMob 앱 심사(보통 2~3일)가 끝나야 광고 제한이 풀림
- [ ] `app-ads.txt` 안내가 나오면 따름
- [ ] 문의 확인(앱 안 문의 게시판 운영안 참조), 주 1회 지표 보기

## 9. 막혔던 것 모음(다음에는 미리 피하기)

- 스크린샷이 세로로 너무 길면 금지 표시 → 9:16으로 자르기
- 방침 주소가 `.html`을 빼고 자동으로 다른 주소로 넘어가서 확인 도구가 못 찾음 → 확인할 때 따라가기(redirect) 옵션 사용
- PowerShell에서 `npx`가 막히면 `npx.cmd` 사용. 새 창은 토큰을 다시 설정해야 함
- 화면 캡처에 토큰 앞부분이나 이메일·주소가 보이지 않게 가려서 올릴 것
- 판매자 신고 화면: 광고 수익 앱은 판매자로 신고하는 것이 구글 안내와 맞음(아니라고 하면 허위 신고)
- 이메일 목록 만들기: 이메일 입력칸에서 Enter를 눌러야 목록에 추가됨
- 앱 설명을 고치면 콘솔에서 따로 다시 저장·제출해야 반영됨

## 10. 지키는 정책

- 리뷰·별점 대가로 보상 금지, 가짜 리뷰 금지
- 공식 서비스로 오해하게 쓰지 않기(소방청 등 로고·이름 금지)
- 광고 있음을 숨기지 않기
- 개인정보는 꼭 필요한 것만, 앱 동작과 방침·설문이 같아야 함
- 새 개인정보 기능을 넣기 전에 대표에게 먼저 확인
